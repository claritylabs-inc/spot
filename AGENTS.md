# AGENTS.md

Guidance for coding agents in this repository. Read `CLAUDE.md` and, before Convex code changes, `convex/_generated/ai/guidelines.md`. Ground changes in the current code and preserve unrelated worktree edits.

## Testing and documentation

Prefer browser workflow QA for complex features. Do not write unit tests after writing code. An isolation test is justified only for a failure E2E cannot reliably catch, such as authorization, tenant isolation, webhook signatures, replay, leases, idempotency, fail-closed behavior, or a compact domain invariant; list failure modes before implementing an isolated system. `docs/testing/workflow-qa.md` owns the E2E coverage ledger and repeatable artifacts. Use Node 24.x. Keep `AGENT_TOOLS.md` synchronized with every material model-callable or MCP tool change. Update this file after major architecture changes. Use `dayjs` for new or touched date logic.

## Product and data boundaries

- `markdownDocuments` owns mutable company wiki and procurement prose. A request has exactly `private.md` for operator work and `public.md` for authorized shared content. The filename fixes visibility; server authorization fixes readership. Front matter cannot grant access. `convex/markdownDocuments.ts` and `convex/lib/markdownDocument.ts` own storage, YAML parsing, size limits, and revision checks. The inline editor is `components/ui/markdown-editor.tsx`; source and rich editors live beside it. Opening or switching views does not write. Issued snapshots remain immutable; active packet links show saved `public.md` and currently released files. Regeneration rotates a link, while content edits do not.
- Company details are Markdown prose. Organizations retain identity, research state, and operational access fields. Policy identity, address, and operations come from policy evidence and policy-specific overrides, never company prose. Do not infer subsidiaries from additional named insureds. `convex/companyResearch.ts` and `convex/actions/companyResearch.ts` own automatic public research on creation and identity edits. Logo import runs for client organizations with a website and no logo.
- Procurement requests are client-visible by default. Clients see `public.md` and separately client-visible request files, never `private.md`, proposals, or operator-private market activity. Request file visibility for clients and brokers is independent and defaults off for uploads. `procurementFileItems` requires a `clientFileId`; legacy placeholders are omitted. Client request DTOs are allowlisted. Broker members have profile/team-only access; policy and procurement staff mutations are operator-only.
- Pending email drafts store typed delivery fields; replacing one clears removed recipients and attachments and invalidates its exact approval. Notifications have no age-based unread expiry. Slack attachment intake enforces stored-byte budgets through `convex/lib/slackAttachments.ts`.

## Convex section extraction and search

Policy and proposal extraction run in Convex. `convex/lib/pdfText.ts` and `convex/lib/pdfSourceSpans.ts` extract pdf.js text, lines, and positioned spans. `convex/lib/policySectioning.ts` groups pages by printed form number and Jev decisions, then slices each section's original PDF. `convex/lib/sectionExtraction/` runs one durable router job per section; declarations complete first and supply a preview and context for other sections. `convex/lib/citationResolver.ts` resolves page-and-quote citations to evidence spans. Pages without a text layer receive cited model-transcription spans. `convex/lib/extractionPromotion.ts` gates final promotion on a complete `convex-sections-v1` manifest and grounded evidence. `promoteCompletedExtractionInternal` is the sole final writer; operator overrides survive extraction. The operator policy page has a Sections tab, and `lib/extraction-state.ts` owns shared status presentation. See `docs/architecture/convex-section-extraction.md`.

The former Railway extraction worker, LiteParse/Poppler/OCR, preview queue, `source-tree-v2`, and legacy policy support are removed. The cl-sdk extraction engine is unused and marked deprecated in cl-sdk. Spot still uses its schemas, taxonomy, source-tree helpers, PDF form filling, and prompts. There are no `documentChunks` writes or chunk embeddings. Agent policy retrieval uses Convex full-text search and Jev relevance ranking in `convex/lib/policySearch.ts` and `convex/lib/policyLookup.ts`. `convex/actions/reextractLegacyPolicies.ts` provides a bounded migration action and defaults to dry-run.

## AI and agent execution

- All model generation, decisions, embedding, transcription, and credentialed retrieval go through `CL_ROUTER_URL` and `CL_ROUTER_SECRET`; Spot holds no provider credentials. `convex/lib/clRouterClient.ts` and `convex/lib/clRouterPrimitive.ts` own the transport and task mapping. Router failures fail closed. Rich asset and serialized request limits remain enforced. `convex/routerJobs.ts`, `convex/lib/routerJobClient.ts`, and `convex/actions/routerJobs.ts` own durable jobs, private payloads, scoped assets, callback capabilities, cancellation, and reconnection. Unknown outcomes never replay an inference step. See `docs/architecture/router-jobs.md`.
- `clRouterDecide` provides Jev Choice/Noul decisions. `convex/lib/jevThreshold.ts` centralizes the 0.7 confidence rule: proceed only when the selected choice reaches it. Prompt screening treats content as safe only when the safe choice reaches that threshold. Jev selects among known candidates for intake, page sections, carrier identity, coverage scoping, grounding fallback, organization names, mailbox automation, and other classifications; generation supplies prose and extracted values. `convex/lib/clientAgentPrompt.ts` chooses optional prompt modules, answer depth, and Slack reaction. `convex/lib/channelControls.ts` classifies email, Slack, and certificate endorsement intents. Email send authorization is stored on the message as `emailSendAuthorization`.
- Operator tool families are selected with Jev and expanded with `expand_tools`. The active role, impersonation, configured integrations, exact target authorization, and approval are rechecked at execution. `convex/lib/operatorAgentToolRegistry.ts` owns the registry. The global **Approve all** switch on `/operator/settings` is off by default and automatically satisfies new exact approvals only when enabled; existing pending approvals still require a decision. Tenant approvals are separate. The same runner serves operator web, email, Slack, iMessage, and MCP channels.
- Operator email at `operator@agent.spot.insure` requires verified webhook delivery and aligned full-body DKIM before resolving an active operator. Quoted history is separate from current instructions. Email replies cannot approve exact writes. `convex/operatorEmail.ts` and `convex/actions/handleInboundOperatorEmail.ts` own ingress and recovery. Operator identity matches normalized localparts across the exact `toolsforenlightenment.org`, `spot.insure`, and `claritylabs.inc` domains after mailbox verification.
- The shared chat component architecture is in `components/chat/`. `lib/chat-presentation.ts`, `lib/chat-presentation-catalog.ts`, `convex/lib/chatPresentationCandidates.ts`, `convex/lib/chatPresentationComposer.ts`, and `convex/chatPresentations.ts` own grounded presentations and current-reference authorization. Composition cannot execute business tools.

## Integrations and UI

- Tenant MCP tools project from `convex/lib/tenantMcpToolCatalog.ts`; operator MCP projects the operator registry. Legacy `/mcp/*` REST paths and `ask_glass` are removed. OAuth access and exact resource authorization remain enforced. See `AGENT_TOOLS.md`.
- Browser WebMCP is off by default behind Vercel flag `webmcp-enabled` in `lib/flags.ts`. `WEBMCP_ENABLED=true` enables its default decision, and `FLAGS_SECRET` permits Vercel Toolbar overrides. The catalog lives in `lib/webmcp/catalog.ts`. See `docs/architecture/webmcp.md`.
- Google Workspace mailbox reconciliation is a read-only `scan_workspace_mailbox` operator tool, with no scheduled scan. Agent-scheduled workflows are tracked in Linear CLA-171. Presence cleanup is unscheduled (CLA-170).
- Page tabs use plain labels, preserve the primary view, and hide empty secondary views. Operator pages use app-shell breadcrumbs and `TabsList variant="pill"`; do not repeat route titles in content. Use `PillButton` for pill actions, including destructive ones with `variant="destructive"`. Shared primitives are listed in `.agents/skills/spot-primitives/SKILL.md`.
- `main` release readiness is owned by `.github/workflows/deploy-convex.yml` and `docs/deployment/environments.md`. Do not deploy or run production cleanup through local validation. Use `gh stack` for related reviewed stacks, with `stack/<topic>/<layer>` intermediates and `preview/<topic>` at the top. Do not rename an existing workspace branch without explicit authorization.

## Post-deploy operator checklist for this extraction release

After the release deploys to an approved target:

1. Decommission the Railway `spot-extraction-worker` service.
2. Remove `EXTRACTION_WORKER_*` and `LITEPARSE_*` variables from Convex deployments.
3. Run `npx convex run actions/reextractLegacyPolicies:run '{"dryRun":true}'`, then repeat with `{"dryRun":false}` after review. Page with the returned cursor until `isDone`. Run `npx convex run modelSettings:stripRetiredRoutesInternal '{}'` and `npx convex run modelSettings:clearOperatorModelOverridesInternal '{}'`, paging each returned `continueCursor` until `isDone`. Select the intended deployment explicitly and use `--prod` only for an approved production run.
4. Drop schema tables and fields marked `// Deprecated` after data cleanup and verification on every deployed target.
5. Set `FLAGS_SECRET` and `WEBMCP_ENABLED` where WebMCP should be available.
6. Run prompt-module evals with `CL_ROUTER_EVALS=1 npx vitest run convex/lib/__evals__/clientAgentModules.eval.test.ts`.

The operator-agent model route and web retrieval route have no settings UI. Set the operator agent route with `npx convex run modelSettings:setOperatorAgentRouteInternal '{"provider":"openai","model":"..."}'`. `modelSettings:clearOperatorModelOverridesInternal` clears every other stored override but keeps the operator agent route, which `resolveOperatorAgentRoute` still requires. Web retrieval falls back to its default when no override is stored.
