# AGENTS.md

Guidance for coding agents in this repository. Read `CLAUDE.md` and, before Convex code changes, `convex/_generated/ai/guidelines.md`. Ground changes in the current code and preserve unrelated worktree edits.

## Testing and documentation

Prefer browser workflow QA for complex features. Do not write unit tests after writing code. An isolation test is justified only for a failure E2E cannot reliably catch, such as authorization, tenant isolation, webhook signatures, replay, leases, idempotency, fail-closed behavior, or a compact domain invariant; list failure modes before implementing an isolated system. `docs/testing/workflow-qa.md` owns the E2E coverage ledger and repeatable artifacts. Use Node 24.x. Keep `AGENT_TOOLS.md` synchronized with every material model-callable or MCP tool change. Update this file after major architecture changes. Use `dayjs` for new or touched date logic.

## Product and data boundaries

- `markdownDocuments` owns mutable company wiki and procurement prose. A request has exactly `private.md` for operator work and `public.md` for authorized shared content. The filename fixes visibility; server authorization fixes readership. Front matter cannot grant access. `convex/markdownDocuments.ts` and `convex/lib/markdownDocument.ts` own storage, YAML parsing, size limits, and revision checks. Agent-authored company prose is not rejected by keyword blacklists; policy/company boundaries are tool guidance, while authorization, revisions and document validation remain enforced. The inline editor is `components/ui/markdown-editor.tsx`; source and rich editors live beside it. Opening or switching views does not write. Issued snapshots remain immutable; active packet links show saved `public.md` and currently released files. Regeneration rotates a link, while content edits do not.
- Submitted company facts live in typed `organizations.intakeBusinessProfile`; research and freeform company notes remain Markdown prose. Operator edits and document imports prioritize `update_client_business_profile` for actual company fields, with version checks and exact approval; `update_client_wiki` is for supplementary notes. Operator Profile uses pill tabs for account, business, addresses, related entities, revenue, locations and notes; Markdown stays in a Notes card with its own controls. Organizations retain identity, research state, and operational access fields. Policy identity, address, and operations come from policy evidence and policy-specific overrides, never company prose. Do not infer subsidiaries from additional named insureds. `convex/companyResearch.ts` and `convex/actions/companyResearch.ts` own automatic public research on creation and identity edits. Logo import runs for client organizations with a website and no logo.
- Procurement requests are client-visible by default. Clients see `public.md` and separately client-visible request files, never `private.md`, proposals, or operator-private market activity. Request file visibility for clients and brokers is independent. New request uploads default to broker-attached; explicit broker hiding remains enforced. Client visibility retains its separate defaults. `procurementFileItems` requires a `clientFileId`; legacy placeholders are omitted. Client request DTOs are allowlisted. Broker members have profile/team-only access; policy and procurement staff mutations are operator-only.
- `convex/lib/emailTools.ts` owns discrete draft, update, policy/file/COI attachment, list, send, and cancel tools shared by client agents and tenant MCP. No nested email subagent remains. Sends require the current actor-bound message’s stored Jev authorization or an existing exact-confirmation/review path; direct MCP sends retain their separate explicit-action path, which `ask_spot` cannot use. Recipient, attachment, COI evidence, and duplicate checks remain enforced. Pending email drafts store typed delivery fields; replacing one clears removed recipients and attachments and invalidates its exact approval. Notifications have no age-based unread expiry. Slack attachment intake enforces stored-byte budgets through `convex/lib/slackAttachments.ts`.
- `convex/lib/mailboxTools.ts` owns the discrete connected-mailbox family, shared multi-account search, search logs, and deterministic evidence for email references actually used. Web/Slack, direct internal email, linked-user iMessage, MCP chat, and tenant MCP share these executors. Imports, saves, and vendor invitations require write access. Direct MCP saves require an authorized thread; private threads remain creator-only. The mailbox coordinator and `coordinate_mailbox_task` are removed; all calls appear in the parent audit.

## Convex section extraction and search

Policy and proposal extraction run in Convex. `convex/lib/pdfText.ts` and `convex/lib/pdfSourceSpans.ts` extract pdf.js text, lines, and positioned spans. `convex/lib/policySectioning.ts` groups pages by printed form number and Jev decisions, then slices each section's original PDF. `convex/lib/sectionExtraction/` runs one durable router job per section; declarations complete first and supply a preview and context for other sections. `convex/lib/citationResolver.ts` resolves page-and-quote citations to evidence spans. Pages without a text layer receive cited model-transcription spans. `convex/lib/extractionPromotion.ts` gates final promotion on a complete `convex-sections-v1` manifest and grounded evidence. `promoteCompletedExtractionInternal` is the sole final writer; operator overrides survive extraction. The operator policy page has a Sections tab, and `lib/extraction-state.ts` owns shared status presentation. See `docs/architecture/convex-section-extraction.md`.

The former Railway extraction worker, LiteParse/Poppler/OCR, preview queue, `source-tree-v2`, and legacy policy support are removed. The cl-sdk extraction engine is unused and marked deprecated in cl-sdk. Spot still uses its schemas, taxonomy, source-tree helpers, PDF form filling, and prompts. There are no `documentChunks` writes or chunk embeddings. Agent policy retrieval uses Convex full-text search and Jev relevance ranking in `convex/lib/policySearch.ts` and `convex/lib/policyLookup.ts`. `convex/actions/reextractLegacyPolicies.ts` provides a bounded migration action and defaults to dry-run.

## AI and agent execution

- All model generation, decisions, embedding, transcription, and credentialed retrieval go through `CL_ROUTER_URL` and `CL_ROUTER_SECRET`; Spot holds no provider credentials. `convex/lib/clRouterClient.ts` and `convex/lib/clRouterPrimitive.ts` own the transport and task mapping. Router failures fail closed. Rich asset and serialized request limits remain enforced. `convex/routerJobs.ts`, `convex/lib/routerJobClient.ts`, and `convex/actions/routerJobs.ts` own durable jobs, private payloads, scoped assets, callback capabilities, cancellation, and reconnection. Unknown outcomes never replay an inference step. See `docs/architecture/router-jobs.md`.
- `clRouterDecide` provides Jev Choice/Noul/Score decisions and, through cl-router's images mode, image inputs and Box localization. `convex/lib/pdfPageImages.ts` renders PDF pages for Jev and `convex/lib/jevImages.ts` stages images and locates text on a page (presence Noul plus zoomed Box). Image and Box answers are experimental: they never solely gate irreversible writes and failures fall back to text. Decompose questions into atomic, self-contained Nouls over structured state and keep deterministic rules in code. `convex/lib/jevThreshold.ts` centralizes the confidence rule: proceed only when the selected choice reaches the threshold, 0.7 by default and set with the Convex env var `JEV_PROCEED_THRESHOLD` (0.5–0.99, read per call). Prompt screening treats content as safe only when the safe choice reaches that threshold. Jev selects among known candidates for intake, page sections, carrier identity, coverage scoping, grounding fallback, organization names, mailbox automation, and other classifications; generation supplies prose and extracted values. `convex/lib/agentToolSelection.ts` owns shared family selection, availability, required families, intent shortcuts, fallback, expansion schemas, guidance, and telemetry. `convex/lib/clientAgentPrompt.ts` selects client families, answer depth, and Slack reaction in one Jev call, then uses AI SDK `prepareStep` for active tools and guidance; `expand_tools` loads families on the next step of the same turn. Used families stay active, and selection cannot grant tools excluded by surface or authorization. `convex/lib/channelControls.ts` classifies email, Slack, and certificate endorsement intents. Email send authorization is stored on the message as `emailSendAuthorization`.
- Certificate endorsement eligibility uses stored, cited insured/class candidates and Jev endorsement decisions; uncertainty or router failure holds issuance. Carrier identity selects retrieved sites and name relationships with Jev, then retains deterministic metadata naming and source grounding. Compliance manual review asks Jev atomic per-policy questions (insured, coverage, provisions) and derives status in code from deterministic limit and date checks. Company research starts deterministically, verifies identity with per-candidate Jev checks and a tie-break choice only when several sites pass, and retains generation only for profile prose. Proposal review generates section findings; code derives the overall conclusion.
- Research, requirement extraction, supplementary extraction, proposal review, and title generation carry task kinds and parent/job traces. Research retrieval traces are stored in Spot's durable job metadata because the router retrieval request contract does not accept trace fields. `convex/actions/threadTitle.ts` owns title generation for client threads, including MCP, and operator Slack.
- Operator goal planning uses `convex/lib/operatorPlanning.ts` and `operatorRunPlan.ts`: four independent Jev Nouls, deterministic confident-no-only skip, then a separate durable structured plan before business tools. The run and assistant message retain the plan. `operatorToolRecovery.ts` bounds correctable no-write failures to three subsequent model iterations, persists recovery with continuation, and excludes exhausted tools; it never authorizes unknown writes or bypasses approvals. `operatorAgentToolFailure.ts` owns structured codes and guidance; `NoWriteInputError` carries known pre-write failures across Convex boundaries. Tool schemas still validate before dispatch. Search/list tools disclose scan and result bounds; failed or incomplete searches cannot prove absence.
- Operator tool families use the shared selector with existing intent shortcuts and all-family durable resume behavior, and expand with `expand_tools` on the next scheduled step. The active role, impersonation, configured integrations, exact target authorization, and approval are rechecked at execution. `convex/lib/operatorAgentToolRegistry.ts` owns the registry. The global **Approve all** switch on `/operator/settings` is off by default and automatically satisfies new exact approvals only when enabled; existing pending approvals still require a decision. Tenant approvals are separate. The same runner serves operator web, email, Slack, iMessage, and MCP channels.
- Operator email at `operator@agent.spot.insure` requires verified webhook delivery and aligned full-body DKIM before resolving an active operator. Quoted history is separate from current instructions. Email replies cannot approve exact writes. `convex/operatorEmail.ts` and `convex/actions/handleInboundOperatorEmail.ts` own ingress and recovery. Operator identity matches normalized localparts across the exact `toolsforenlightenment.org`, `spot.insure`, and `claritylabs.inc` domains after mailbox verification.
- Processing web messages carry bounded live `activity` (tool name, call id, status), recorded by the runners and optional router `toolCalls` progress metadata. Requested calls are not yet running, and returned calls do not imply business success. Show thinking defaults to visible while preserving explicit opt-outs. `convex/lib/messageActivity.ts` owns the state contract.
- The shared chat component architecture is in `components/chat/`. Bounded message activity retains observed preparation, tool/model selection, and tool lifecycle stages through completion or failure. Router stages arrive through the authenticated progress capability; never expose decision inputs, raw reasoning, or provider error bodies in the chat trace. `lib/chat-presentation.ts`, `lib/chat-presentation-catalog.ts`, `convex/lib/chatPresentationCandidates.ts`, `convex/lib/chatPresentationComposer.ts`, and `convex/chatPresentations.ts` own grounded presentations and current-reference authorization. Composition cannot execute business tools.
- The browser extension in `extensions/spot/` hosts the client agent at `/extension`, reusing chat, history, attachments and detail panels. `config/browser-extension.json` and `lib/browser-extension.ts` own the exact-origin, bounded page-capture bridge. Capture requires an explicit browser action and stages a removable attachment; it never submits a message or executes tools. Keep authentication and business authorization in the app/backend, with no extension token relay. See `docs/architecture/browser-extension.md`.

## Insurance request intake

Restricted unverified users can access only their own drafts and uploads. `/api/intake` and `requestHandoffs` provide an expiring, hashed landing handoff; existing emails require OTP before access and new accounts can submit before verifying, then confirm email from the submitted application banner. `components/insurance-intake/` owns focused conditional questions, the shared intake frame, local recovery, and the editable post-submission application overview. Requirement uploads reuse `convex/actions/complianceRequirements.ts` through one-shot `convex/actions/intakeRequirementPrefill.ts` and request-owned suggestions; failures stay server-only and suggestions never overwrite entered answers. Coverage lines own their limits, additional requests, and bounded property/vehicle scope; company-level lines bypass item scope. Submitted edits preserve the original snapshot. Submission preserves the original snapshot and writes the canonical typed `intakeSubmittedApplication`; admin submissions promote an allowlisted `intakeBusinessProfile`. Draft saves never publish facts. Markdown is a sharing/export projection, with authored notes and control markers retained. The manual intake readiness checklist and lifecycle gate are removed; procurement uses its ordinary lifecycle controls. Application and company views render typed facts through shared intake row-card components. Shared packet exports generate Markdown tables from the accepted application, hiding control comments only in presentation and retaining them in source. `convex/intakeSlack.ts` owns the request-scoped Slack outbox: one #submissions thread, untagged step progress, and @here only on submitted/resubmitted events, delivered through the Convex Slack Web API transport (`convex/lib/slackWebApi.ts`). See `docs/architecture/insurance-intake.md`.

Quote intake uses reviewed local catalog packs in Coverage, then terminal routed LLM follow-ups after history, before review. Each follow-up is one page within its section; `IntakeDetails.followupProgress` persists its position (sections 29/30, legacy review 28). `docs/procurement/acord-intake/question-catalog.json` owns the original Spot catalog imported from PR #519 (unverified ACORD mappings); `lib/intake-acord-questions.ts` adapts it to intake primitives and coverage/dependency gates; `convex/actions/intakeFollowups.ts` and `requestIntake.prepareFollowups` own bounded, context-versioned generation. `lib/intake-question-history.ts` pairs base/follow-up questions with answers and skip status for generation and gap assessment; base facts are reserved even when blank. The terminal pass uses one structured generation call for gap assessment, semantic novelty and input choice; it has no separate model gate, screening or Boolean-prefill call. `lib/intake-question-reference.ts` selects at most 50 reviewed, coverage-mapped historical question concepts (12,000 characters) as hints, never universal requirements. Raw source accounts and answers never enter the pack. Saved question definitions/answers remain request-owned, survive submission, and are excluded from company-profile promotion. Savings reviews skip both sections. Bounded local additional-question generation explicitly uses the router synchronous endpoint (text-only, no tools, at most 3,000 output tokens); hosted calls remain durable, and unknown inference outcomes never replay.

`organizations.clientAccessStatus` (`limited` by default, or `active`) is the only client status. Operators set it from the client list/detail/editor (`operator:setSoloClientStatus`), the `set_client_access_status` operator tool, and launch emails, which activate the client. Limited clients are routed to `/signup`; active client home routes to `/requests`. The retired `operatorStatus` is gone; there are no lost/churned states, pending-live screens, or onboarding-only gates. Operator impersonation passes org auth gates as target-org admin (`OrgAccess.impersonated`) and every guarded write is audited as `impersonated_write` by `recordImpersonatedWrite`; operator-console-only actions still reject during impersonation. This does not replace server resource authorization.

## Post-deploy operator checklist for this extraction release

After the release deploys to an approved target. Steps 2–3 can run in production through the manual `post-deploy-maintenance` GitHub workflow (`gh workflow run post-deploy-maintenance.yml -f task=<task>`), which uses the repository's production deploy key:

1. Decommission the Railway `spot-extraction-worker` service.
2. Remove `EXTRACTION_WORKER_*` and `LITEPARSE_*` variables from Convex deployments.
3. Run `npx convex run actions/reextractLegacyPolicies:run '{"dryRun":true}'`, then repeat with `{"dryRun":false}` after review. Page with the returned cursor until `isDone`. Run `npx convex run modelSettings:stripRetiredRoutesInternal '{}'` and `npx convex run modelSettings:clearOperatorModelOverridesInternal '{}'`, paging each returned `continueCursor` until `isDone`. Select the intended deployment explicitly and use `--prod` only for an approved production run.
4. Drop schema tables and fields marked `// Deprecated` after data cleanup and verification on every deployed target.
5. Set `FLAGS_SECRET` and `WEBMCP_ENABLED` where WebMCP should be available.
6. Verify client-family behavior through the browser workflow QA ledger; the opt-in unit eval suite was retired in the October 16 test reduction.

The operator-agent model route and web retrieval route have no settings UI. Set the operator agent route with `npx convex run modelSettings:setOperatorAgentRouteInternal '{"provider":"openai","model":"..."}'`. `modelSettings:clearOperatorModelOverridesInternal` clears every other stored override but keeps the operator agent route, which `resolveOperatorAgentRoute` still requires. Web retrieval falls back to its default when no override is stored.

Operator procurement deletion is recoverable through `procurementRequests.remove` / `restore`, with direct-operator authorization, impersonation protection, and audit records. Deleted requests are excluded from lists and deny application/shared-packet access; company files and policies remain intact.

Admin inline row layout uses one left-aligned value column for text, numbers, addresses, and dropdowns, with labels capped at 20rem/35% and side-by-side label/value pairs on narrow screens. Labels and controls are vertically centered within each row; single-line inputs and dropdown triggers share a 36px height. Long-text inputs size to their content from one line and align their labels to the first line; long dropdown values wrap; idle dropdown chevrons stay hidden until focus/open. Keep this contract in `components/ui/inline-fields.tsx` and its scoped rules in `app/globals.css`.

Removed file associations cannot be edited back into visibility. Delete request lives in the navbar and retains the existing recoverable deletion confirmation.
